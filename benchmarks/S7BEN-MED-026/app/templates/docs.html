All API endpoints (except login and public pages) require an authenticated session. Send a POST to /api/login first to obtain a session cookie, then include that cookie in subsequent requests.

Authentication

POST /api/login
Authenticate and receive a session cookie. 
{"username": "string", "password": "string"}
POST /api/logout
Clear the current session.

Packages

GET /api/packages
List all registered packages with their latest version and owner.
GET /api/packages/{name}
Get detailed information about a package, including all published versions and their build automation scripts.
POST /api/packages/{name}/versions
Publish a new version of a package. The request body should include version number, description, and optional build automation scripts. 
{
  "version": "1.0.1",
  "description": "Release notes here",
  "scripts": {
    "postinstall": "echo 'Setup complete'"
  }
}

Builds

POST /api/builds
Trigger a new build. Specify packages to install. The build system installs the latest version of each package and runs any configured build automation scripts. 
{"packages": ["forge-core", "forge-auth"]}
GET /api/builds
List all builds for the current user.
GET /api/builds/{id}
Get build details including status and execution log.

Build Automation Scripts

Packages can define scripts that run automatically during the build process:

  • postinstall — Runs after a package is installed during a build. Commonly used for setup tasks, configuration generation, or environment initialization.

Scripts are defined as part of the version metadata when publishing a new version.

Version Format

Versions follow semantic versioning: MAJOR.MINOR.PATCH (e.g., 1.0.0, 2.1.3). The build system always installs the latest available version of each requested package.
